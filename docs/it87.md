# it87 driver on the Beelink ME Mini

The ME Mini's ITE IT8613E Super I/O is controlled through the out-of-tree
[`it87` driver](https://github.com/frankcrawford/it87). The in-tree Linux
module may not bind or may be missing the chip-specific handling needed for
fan control. This is the setup used on the validated ME Mini.

> **Warning:** this is a kernel module and it writes to the embedded
> controller. A wrong PWM value can stop the fan. Read the whole page, keep a
> terminal open, and monitor temperatures while testing.

## Tested environment

| | |
|---|---|
| Model | Beelink ME Mini (`AZW` / `ME mini`), BIOS `N5X12002` |
| OS / kernel | Debian 13, `6.12.115+deb13.1-amd64` |
| Super I/O | ITE IT8613E, revision 12, at `0xa30` |
| Driver | `frankcrawford/it87`, DKMS package `it87-driver`, version `20f2f2f.20260416` |
| Secure Boot | disabled / Setup Mode on the tested machine |

## Install

```sh
sudo apt update
sudo apt install dkms build-essential git linux-headers-"$(uname -r)" lm-sensors

git clone https://github.com/frankcrawford/it87
cd it87
sudo ./dkms-install.sh
sudo modprobe it87
```

The DKMS install places the module under
`/lib/modules/$(uname -r)/updates/dkms/it87.ko*`, which takes precedence over
the in-tree module.

## Module options

On the ME Mini the ACPI firmware claims the Super I/O region, so the module
needs to ignore that resource conflict. The tested configuration is:

```sh
# /etc/modprobe.d/it87.conf
options it87 ignore_resource_conflict=1
```

```sh
# /etc/modules-load.d/it87.conf
it87
```

Then rebuild the initramfs if your distribution requires it and reboot, or
`sudo modprobe it87` for the current boot.

`ignore_resource_conflict=1` makes both ACPI and the driver access the chip.
The driver documentation warns that this can cause races and, worst case,
unexpected reboots. Use it only when needed. `acpi_enforce_resources=lax` is
the system-wide alternative; it is riskier and was **not** needed here.

Do not use `force_id` or `fix_pwm_polarity` unless you are debugging a
different board and know what you are doing.

## Verify

```sh
dmesg | grep -i it87
# it87: Found IT8613E chip at 0xa30, revision 12
# it87: Beeping is supported

lsmod | grep it87
sensors
```

You should see an `it8613-isa-*` block with `fan2`, `pwm2`, `pwm3`, `pwm5`
and several temperatures. The CPU fan on this board is `fan2` / `pwm2`;
see [hardware](hardware.md).

Check the mode and values:

```sh
H=$(grep -l it8613 /sys/class/hwmon/*/name | xargs dirname)
cat "$H/pwm2_enable"   # 2 = automatic, 1 = manual
cat "$H/pwm2"
cat "$H/fan2_input"
```

`pwm2_enable = 2` means the EC is in control; `1` means manual control.
`sb-daemon` sets `1` while running and restores `2` on shutdown.

## Secure Boot

The tested machine has Secure Boot disabled and is in Setup Mode, so the
DKMS module loads without enrollment. If Secure Boot is enabled:

```sh
sudo mokutil --import /var/lib/dkms/mok.pub
sudo reboot
# In the MOK manager: Enroll MOK -> Continue -> Yes -> password -> reboot
```

The DKMS module is already signed with the DKMS key:

```sh
modinfo it87 | grep -E 'signer|sig_key'
```

The kernel log may still say `module verification failed` when Secure Boot is
off; that is a taint warning, not a load failure.

## Kernel updates

Keep `linux-headers-amd64` installed. DKMS rebuilds the module for each new
kernel automatically:

```sh
sudo apt install linux-headers-amd64
dkms status
```

After a kernel update, reboot and check `dmesg | grep -i it87`. If the module
is missing, install the headers for the running kernel and run:

```sh
sudo dkms autoinstall
```

## Remove

```sh
cd it87
sudo ./dkms-remove.sh
sudo rm -f /etc/modprobe.d/it87.conf /etc/modules-load.d/it87.conf
sudo modprobe -r it87
```

If the CPU fan is still in manual mode, restore automatic control first:

```sh
echo 2 | sudo tee /sys/class/hwmon/hwmon*/pwm2_enable
```

## Risks

- Out-of-tree modules taint the kernel and can break on kernel API changes.
- Resource-conflict workarounds mean the driver and ACPI may both touch the
  embedded controller.
- The EC owns the fan when `pwm2_enable = 2`; while `sb-daemon` runs it is
  manual. A crash or SIGKILL can leave the fan at the last manual value until
  the service restarts or the machine reboots.
- Other ME Mini BIOS versions, board revisions or IT87 variants may route the
  fan differently. Use [`tools/collect-me-mini.sh`](../tools/collect-me-mini.sh)
  and `sb-daemon --check` before trusting a channel.
